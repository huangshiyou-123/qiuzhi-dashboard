# 求职作战台

> 求职全流程 AI 工具：JD 解析 → 话术生成 → 简历优化 → 面试备战 → 投递追踪 → 数据分析，一站式闭环。
>
> **零安装、零后端、零费用。** 双击即用，所有数据存本地。

---

## 为什么要做这个

求职过程中有几个割裂的环节：

- 看到 JD → 截图发给 AI 分析 → 复制结果回来 → 手动记投了哪家
- 每家 JD 不同 → 每次重新写打招呼话术 → 每次重新改简历
- 投了 30 家公司 → 记不住哪些已读、哪些已回、哪些该跟进

市面上豆包、Kimi 能分析单条 JD，但没有工具把「JD 解析 → 话术 → 简历 → 追踪 → 数据分析」串成完整闭环。

**求职作战台解决了这个问题。** 粘贴一条 JD，后续所有模块自动联动。

## 功能模块

### 1. JD 深度解析

粘贴 JD 文本或上传截图，AI 自动输出七段分析：

- **基本信息** — 公司、岗位、薪资、地点、学历/经验要求
- **公司解码** — 这家公司到底做什么的、什么阶段、你在什么位置
- **日常一天推测** — 入职后每天具体做什么事，带时间占比
- **硬性门槛 vs 加分项** — 明确区分，知道哪些是必须的
- **面试官真正想听的三件事** — 具体到场景级
- **话术切入角度** — 打招呼角度 + 简历强调项 + 面试话题
- **风险提示** — 可能的坑

> 设计意图：不只提取字段，还帮你理解这家公司、判断是否值得投。

### 2. 智能话术生成

JD + 你的简历 → 三步走生成三种 BOSS 直聘打招呼话术：

- **标准版** — 专业得体，含具体匹配点，让 HR 觉得你研究过 JD
- **热情版** — 展示对公司业务的了解，主动提及 JD 中的产品/方向
- **简洁版** — 60 字以内，对方在线时快速发送

> 流程：AI 先拆解 JD 核心需求 → 从简历中找到具体匹配点 → 基于匹配结果生成话术。每条话术首行标明到岗信息（实习时长、每周天数、入职时间）。

### 3. 简历优化

基于 JD 分析匹配度，输出：

- 匹配度评分（0-100）
- 匹配分析（哪些符合、哪些缺失）
- 需要强调的经历（已有但需要放大的）
- 需要补充的内容（JD 要求但简历缺失的）
- 优化后的完整简历文本

> 设计原则：不改学历信息，不编造没有的经历，只调整表达和侧重点。

### 4. 面试备战

支持五种题型，AI 根据岗位类型智能适配：

- **全部** — 全套方案（自我介绍 + 专业题 + 行为题 + 反问）
- **自我介绍** — 30 秒 / 1 分钟 / 2 分钟三版
- **专业问题** — 基于 JD 出 5-8 题，附参考答案
- **行为面试** — 3-5 题，STAR 四步拆解（情境 → 任务 → 行动 → 结果）
- **反问面试官** — 3-4 个有深度的问题

> 运营岗会出内容策划和数据题，不会出编程题。岗位类型自动判断。

### 5. 状态看板

七列拖拽式看板：待投 → 已投 → 已读 → 已回 → 面试 → Offer → 挂断

- 鼠标拖拽切换状态
- 点击卡片查看详情、写笔记
- 支持手动添加记录
- 数据持久化，刷新不丢

### 6. Offer 对比器

拿到两个以上 Offer 时：
- 上传截图（千问 OCR 识别）或手动填写
- AI 从薪资、福利、通勤、发展空间等维度逐项对比
- 给出综合建议

### 7. 数据面板

自动统计总投递数、已读率、回复率、面试数，带趋势图和渠道分布图。

## 快速开始

1. 双击 `index.html` 浏览器打开（或用 `求职作战台.exe`）
2. 左侧菜单点「新增岗位」，粘贴 BOSS 直聘 JD
3. 点「AI 解析 JD」，等 10 秒看到结果
4. 切到「话术生成」和「简历优化」，一键生成
5. 保存 → 去「状态看板」拖拽管理
6. 去「数据面板」看整体效率

> 内置免费 API Key（SiliconFlow × DeepSeek），开箱即用。也可在 API 设置中填入自己的 Key。

## 技术栈

| 层 | 方案 | 选择原因 |
|----|------|---------|
| AI 文本 | DeepSeek Chat API（via SiliconFlow） | 国内直连，中文理解好，免费额度够用 |
| AI 视觉 | 通义千问 VL Max | JD 截图 OCR 识别，比浏览器本地 OCR 准 |
| 本地 OCR | Tesseract.js v5 | 浏览器端离线识别，不上传图片 |
| PDF 提取 | pdf.js | 简历 PDF 文字提取 |
| 数据存储 | IndexedDB（Dexie.js 封装） | 结构化查询，大容量，比 localStorage 专业 |
| 图表 | Chart.js 4 | 投递趋势和渠道分布可视化 |
| 拖拽 | 原生 Drag & Drop API | 看板拖拽，零额外库 |
| 前端 | 纯 HTML/CSS/JS 单文件 | 零构建、零部署、双击即用 |

## 工程决策

### 为什么是单文件 HTML？

不需要后端服务。所有 AI 调用走 API，所有数据存本地 IndexedDB。单文件架构不是因为简单，而是恰好匹配需求——零部署、数据隐私、离线可用。`features.js` 按模块拆分是为了代码可维护性。

### 为什么截图走 OCR 而不是直接发给多模态模型？

早期尝试直接把截图发给 AI，发现 DeepSeek Chat 不支持图片输入。改用 Tesseract.js 在浏览器本地跑 OCR——图片不出你的电脑，识别出的文字才发给 AI 做结构化解析。后续加了千问 VL 作为可选的云端 OCR，给用户选择权。

**这个选择背后的产品原则：能用本地方案解决的隐私问题，不上云。**

### 为什么用 IndexedDB 而不是 localStorage？

localStorage 只能存键值对，容量 5MB。随着投递记录积累到几十上百条，需要结构化查询（"本周投了多少家""已读率是多少""按渠道统计"）。IndexedDB 支持索引查询、更大容量（通常几百 MB），是正经数据库。Dexie.js 封装了复杂 API——站在别人肩膀上的工程意识。

### 为什么话术生成三种？

面对不同状态的公司（对方在线/不在线、大厂/创业公司），一种话术不够用。标准版稳妥、热情版展示对公司的了解、简洁版适合对方在线快速发。三种语气的设计来源于真实的聊天场景差异。

### 为什么 JD 解析结果要在模块间复用？

一次 JD 解析消耗约 2000-4000 token。如果话术生成和简历优化各自重新解析 JD，每次额外消耗成本。设计上，解析结果存内存，下游模块直接引用——单次解析，全流程受益。

## 面试可讲

这个项目能聊的点：

1. **产品闭环思维** — 不只做单点工具，而是把「解析→话术→简历→面试→追踪→分析」串成完整链路
2. **用户场景驱动** — 三种话术语气的设计来自真实聊天场景，不是拍脑袋
3. **隐私优先的产品观** — Tesseract.js 本地 OCR + IndexedDB 本地存储 + API Key 不上云
4. **成本意识** — JD 解析结果模块间复用，避免重复 API 调用
5. **零代码产品的工程实践** — 不写代码也能做出复杂工具，靠的是模块化拆解 + API 编排
6. **产品文档能力** — 附带完整 PRD（用户调研→竞品分析→功能设计→技术决策→迭代记录）
7. **渐进式设计** — 只想解析 JD？一个按钮搞定。想全流程管理？所有模块联动
