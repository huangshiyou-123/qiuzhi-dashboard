# 求职作战台

> 求职全流程管理工具：JD解析 → 话术生成 → 简历优化 → 投递追踪 → 数据分析，一站式闭环。

---

## 这个项目是什么

每天在BOSS直聘上刷岗位、截图发AI分析、手动记投递状态——三个环节割裂，效率低下。

求职作战台把这五个环节串成一个工具：
- **JD解析** — 粘贴文本或上传截图，AI自动提取结构化信息
- **话术生成** — 基于JD+你的简历，生成三种语气的打招呼话术
- **简历优化** — 分析JD匹配度，标注需要强调和补充的内容，生成优化版简历
- **状态看板** — 6列拖拽式看板，从"待投"到"挂断"，全程追踪
- **数据面板** — 已读率、回复率、面试转化率、渠道分布，可视化呈现

## 产品决策记录

### 1. 为什么截图识别不上传服务器？

试过直接把图片发给AI（DeepSeek Chat），发现不支持多模态输入。于是改用 Tesseract.js——在浏览器本地跑OCR，图片不出你的电脑，识别出的文字才发给DeepSeek做结构化解析。

这个选择背后是一个产品原则：**能用本地方案解决的隐私问题，不上云。**

### 2. 为什么用IndexedDB而不是localStorage？

localStorage只能存键值对，容量5MB。随着投递记录累积，需要结构化查询（比如"本周投了多少家""已读率是多少"）。IndexedDB支持索引查询、更大容量，是正经数据库。

Dexie.js封装了IndexedDB的复杂API——这个选择是"站在别人肩膀上"的产品意识。

### 3. 话术为什么生成三种？

面对不同状态的公司（对方在线/不在线、大厂/创业公司），一种话术不够用。标准版稳妥、热情版展示对公司的了解、简洁版适合对方在线快速发。三种语气的设计来源于真实的聊天场景差异。

### 4. 为什么是单HTML文件？

不需要后端、不需要服务器、不需要安装。所有AI调用走API，所有数据存本地。单文件架构不是因为简单，而是恰好匹配需求——零部署、数据隐私、离线可用。

## 快速开始

1. 双击 `index.html` 在浏览器打开
2. 点左下角 **API设置**，填入 DeepSeek API Key，粘贴你的通用简历，保存
3. 点 **新增岗位** → 粘贴JD或上传截图 → 点解析
4. 切换到 **生成话术** 和 **优化简历**，生成内容
5. 切换到 **保存记录**，确认信息后保存
6. 去 **状态看板** 拖拽管理投递进度
7. 去 **数据面板** 看整体效率

## 功能模块

| 模块 | 功能 | 亮点 |
|------|------|------|
| 🔍 JD解析 | 粘贴文本 / 上传截图 → AI提取结构化字段 | 截图OCR在浏览器本地运行，不出电脑 |
| 💬 话术生成 | 基于JD+简历 → 标准版/热情版/简洁版 | 三种语气应对不同沟通场景 |
| 📝 简历优化 | 匹配度分析 → 强调点标注 → 优化版生成 | 不改学历，不编造经历 |
| 📋 状态看板 | 6列看板，拖拽切换状态 | 原生Drag & Drop，数据持久化 |
| 📊 数据面板 | 已读率/回复率/趋势图/渠道分布 | Chart.js可视化 |

## 技术栈

| 组件 | 方案 | 选择原因 |
|------|------|---------|
| AI模型 | DeepSeek Chat API | 国内直连，中文理解好 |
| 截图OCR | Tesseract.js v5 | 纯浏览器本地运行，隐私安全 |
| 数据存储 | IndexedDB（Dexie.js） | 结构化查询，大容量 |
| 图表 | Chart.js 4 | 数据可视化 |
| 前端 | 纯HTML/CSS/JS | 零依赖零安装，单文件 |

## 工程亮点（面试用）

1. **多AI Prompt协同** — 三个Prompt复用JD解析结果，避免重复API调用
2. **浏览器端OCR** — Tesseract.js本地识别，截图不出浏览器，隐私安全
3. **IndexedDB持久化** — 结构化数据库而非简单KV存储
4. **拖拽看板** — 原生Drag & Drop API实现状态流转
5. **单文件架构** — 零部署、零安装、数据本地化
6. **模块解耦** — 每个模块独立可用，但通过共享数据模型联动
